Flappy Bird en Godot 4

Guía paso a paso para montar el clon de Flappy Bird desde cero, entendiendo no solo qué hacer sino por qué cada decisión tiene sentido dentro de Godot.

Motor: Godot 4.x Nivel: Principiante Duración: 3–4 horas Lenguaje: GDScript

¿Qué vas a aprender?

Árbol de nodos y escenas reutilizables, CharacterBody2D y físicas 2D, Parallax2D para scroll de fondo, señales entre nodos, Autoload, Timer, Area2D, animaciones con AnimatedSprite2D, CanvasLayer para la interfaz y gestión del ciclo de partida (inicio / game over / reinicio).

¿Por qué separar escenas y scripts?

En Godot, una escena (.tscn) define qué nodos existen y cómo están organizados visualmente. Un script (.gd) define cómo se comportan. Mantenerlos en carpetas separadas es una convención profesional que hace el proyecto más legible y fácil de mantener cuando crece.

Pasos de la Actividad
01

Crea y configura el proyecto

Ajustes de ventana, FPS y assets — la base sobre la que construiremos todo

1.1
Crea el proyecto en Godot 4.

Nombre: flappy-bird. Carpeta vacía. Renderer: Compatibility.

¿Por qué Compatibility?

Godot 4 ofrece tres renderizadores. Compatibility usa OpenGL y es el más ligero y compatible con hardware modesto. Para un juego 2D como este no necesitamos las capacidades avanzadas de Vulkan, así que elegimos el modo más eficiente.

1.2
Ajusta el tamaño de ventana a 288 × 512.

Ve a Proyecto → Configuración → Display → Window. Pon ancho = 288, alto = 512.

¿Por qué 288 × 512?

Son las dimensiones originales del Flappy Bird para móvil. Al trabajar con los mismos sprites del juego original, esta resolución hace que encajen perfectamente sin escalar ni distorsionar. Es un tamaño "pixel perfect" para estos assets.

1.3
Activa el modo de escala canvas_items.

En la misma ventana, sección Stretch → Mode, selecciona canvas_items.

¿Por qué canvas_items?

Si el jugador agranda la ventana, este modo escala todo el contenido proporcionalmente manteniendo la relación de aspecto. Sin esto, el juego simplemente tendría bordes negros o el contenido quedaría en una esquina pequeña. Con canvas_items, el juego siempre ocupa la pantalla de forma correcta sea cual sea el tamaño.

1.4
Limita los FPS a 60.

Application → Run → max_fps = 60.

¿Por qué limitar a 60 FPS?

Sin límite, Godot intentaría ejecutar el juego a la mayor velocidad posible (300, 500, 1000 FPS…). Aunque usamos delta para que el movimiento sea consistente, tener FPS ilimitados consume CPU y GPU innecesariamente. 60 FPS es el estándar en juegos y garantiza experiencia fluida y eficiente.

1.5
Importa los assets.

Copia la carpeta art/ del proyecto original dentro de tu carpeta de proyecto. Godot la detectará automáticamente.

02

Crea el script Global (Autoload)

El cerebro central: puntuación, estado de partida y señales de comunicación

¿Qué es un Autoload?

En un juego hay información que necesitan múltiples escenas a la vez: ¿está el juego en marcha? ¿Cuántos puntos lleva el jugador? Si cada escena guardara su propia copia, podrían desincronizarse. El Autoload es un nodo que Godot carga una única vez al inicio y mantiene siempre activo y accesible desde cualquier script, como una variable global del proyecto entero.

2.1
Crea la carpeta scripts/ y dentro el archivo global.gd. 
GDScript — global.gdextends Node

# SEÑALES — eventos que otros nodos pueden escuchar
signal on_increment_score
signal on_game_start
signal on_game_over

# ESTADO del juego
var score := 0
var is_start := false

func game_start():
    is_start = true
    score = 0
    emit_signal("on_increment_score")
    emit_signal("on_game_start")

func increment_score():
    score += 1
    emit_signal("on_increment_score")

func game_over():
    is_start = false
    get_tree().paused = true
    emit_signal("on_game_over")
¿Qué es una señal (signal)?

Imagina que la tubería necesita avisar a la GUI cuando el pájaro ha perdido. Podría llamar directamente a una función de la GUI, pero entonces la tubería tendría que "conocer" a la GUI (una dependencia directa). Si más adelante cambias la GUI, tienes que tocar también la tubería.

Con señales, la tubería simplemente grita "¡game over!" al aire. Quien quiera escucharlo se conecta. Esto desacopla los nodos y hace el código mucho más flexible y fácil de mantener.

¿Por qué pausar con get_tree().paused?

Al hacer get_tree().paused = true Godot congela todos los nodos del juego de golpe: físicas, _process, timers, etc. Es la forma más sencilla de detener todo sin tener que ir nodo por nodo parando cosas manualmente. La GUI puede seguir funcionando porque sus nodos tienen process_mode = Always.

2.2
Registra el script como Autoload.

Proyecto → Configuración → Autoload → carpeta → selecciona scripts/global.gd → nombre: Global → Añadir.

¿Por qué el nombre importa?

El nombre que pones en Autoload (Global) es el que usarás en todos los scripts para acceder a él: Global.score, Global.game_over(), etc. Si lo llamas diferente, tendrás que cambiarlo en todos los scripts. Mantenerlo en singular y con mayúscula es la convención habitual.

03

Crea la escena del Pájaro (Bird)

El protagonista: físicas, salto, rotación y animación de aleteo

3.1
Nueva escena — nodo raíz: CharacterBody2D.

Escena → Nueva Escena → Otros Nodos → busca CharacterBody2D. Renómbralo Bird.

¿Por qué CharacterBody2D y no RigidBody2D?

RigidBody2D simula física completa: rebotes, fricción, masa, impulsos. Godot toma el control del movimiento y tú solo aplicas fuerzas. Para un personaje de plataformas o un pájaro que queremos controlar con precisión, eso es demasiado impredecible.

CharacterBody2D nos da la propiedad velocity y el método move_and_slide(), pero nosotros decidimos en el código cómo cambia esa velocidad. Tenemos control total: gravedad manual, salto en el momento exacto que queramos.

3.2
Añade los nodos hijos.
📦 Bird [CharacterBody2D] ← bird.gd ├── AnimatedSprite2D [3 frames de aleteo] ├── CollisionShape2D [CircleShape2D] └── AudioFly [AudioStreamPlayer ← wing.wav]
3.3
Configura la animación en AnimatedSprite2D.

Selecciónalo → Inspector → Sprite Frames → Nuevo SpriteFrames. Añade animación fly con los 3 fotogramas (downflap, midflap, upflap). Velocidad: 10 fps. Loop: activado. Ponlo en Autoplay para que arranque sola.

¿Por qué AnimatedSprite2D y no Sprite2D?

Sprite2D muestra una imagen estática. AnimatedSprite2D puede almacenar varias animaciones con múltiples fotogramas y cambiar entre ellas con código (play("fly")). Para el pájaro necesitamos que sus alas se muevan, así que necesitamos la versión animada. Podríamos hacer lo mismo con AnimationPlayer, pero AnimatedSprite2D es más sencillo cuando la animación es solo un spritesheet.

3.4
Configura la colisión: CircleShape2D.

Selecciona CollisionShape2D → Inspector → Shape → Nueva CircleShape2D. Ajusta el radio hasta que rodee el sprite.

¿Por qué forma circular y no rectangular?

El sprite del pájaro es aproximadamente redondo. Si usáramos un rectángulo, los bordes de la caja de colisión sobresaldrían de la imagen y el jugador sentiría que pierde "sin tocar nada". Un círculo se ajusta mejor a la silueta real del pájaro y da una experiencia más justa. En juegos es habitual hacer la hitbox un poco más pequeña que el sprite para que el jugador sienta que puede "raspar" los obstáculos.

3.5
Crea el script bird.gd y asígnalo al nodo Bird. 
GDScript — bird.gdextends CharacterBody2D
class_name Bird           # registra el tipo en el proyecto

const JUMP_VELOCITY = -300.0   # negativo = hacia arriba en Godot

func _physics_process(delta: float) -> void:
    if Global.is_start:
        
        if not is_on_floor():
            # Acumulamos gravedad: cuanto más tiempo cae, más rápido va
            velocity += get_gravity() * delta
        
        if Input.is_action_just_pressed("ui_accept"):
            velocity.y = JUMP_VELOCITY
            rotation = deg_to_rad(-30)   # inclina hacia arriba al saltar
            $AudioFly.play()
    
    move_and_slide()
    rotation_bird()

func rotation_bird():
    # Inclina progresivamente hacia abajo mientras cae
    if velocity.y > 0 and rad_to_deg(rotation) < 90:
        rotation += 2 * deg_to_rad(1)
    elif velocity.y > 0 and rad_to_deg(rotation) > -30:
        rotation -= 2 * deg_to_rad(1)
¿Qué hace _physics_process y por qué no _process?

Godot tiene dos bucles de actualización. _process(delta) se ejecuta en cada frame renderizado (puede variar). _physics_process(delta) se ejecuta a una tasa fija y sincronizada con el motor de físicas (por defecto 60 veces/segundo).

Para todo lo que involucra movimiento, colisiones o físicas siempre usamos _physics_process. Si usáramos _process, el movimiento podría fallar en detectar colisiones correctamente al variar el framerate.

¿Qué es delta y por qué multiplicamos por él?

delta es el tiempo transcurrido desde el frame anterior, en segundos (típicamente ~0.016 s a 60 FPS). Al multiplicar por delta, garantizamos que si el juego va a 30 FPS el pájaro se mueve la misma distancia total que a 60 FPS — solo en pasos más grandes. Sin delta, el juego iría el doble de rápido en un ordenador más potente.

¿Por qué JUMP_VELOCITY es negativo?

En Godot (y en la mayoría de motores 2D) el eje Y va hacia abajo: Y=0 es arriba, Y crece hacia abajo. Por eso "subir" significa tener velocidad negativa en Y. JUMP_VELOCITY = -300 empuja el pájaro hacia arriba. La gravedad luego va sumando velocidad positiva (hacia abajo) de nuevo.

¿Para qué sirve class_name Bird?

Al declarar class_name Bird, Godot registra este tipo en todo el proyecto. Otros scripts podrán escribir if body is Bird para comprobar si el objeto que ha entrado en una zona de colisión es el pájaro (y no una tubería, el suelo u otro elemento). Sin esto, habría que usar grupos o buscar el nodo por nombre, lo cual es más frágil.

04

Crea la escena de la Tubería simple (Pipe)

Un bloque reutilizable — la base de un obstáculo

¿Por qué crear una escena solo para una tubería si luego usaremos un par?

Este es el principio de reutilización en Godot. En lugar de dibujar dos tuberías separadas, creamos una sola vez el "molde" de una tubería y luego lo instanciamos dos veces dentro de pipe_game.tscn: una normal (abajo) y otra girada 180° (arriba). Si algún día cambiamos el sprite de la tubería, cambia automáticamente en ambas.

4.1
Nueva escena — nodo raíz: Area2D.

Renómbralo Pipe.

¿Por qué Area2D y no StaticBody2D?

StaticBody2D es un cuerpo sólido: los objetos físicos rebotan en él. Area2D es una zona de detección: detecta cuando algo entra o sale, pero no "empuja" físicamente.

Usamos Area2D porque queremos detectar que el pájaro toca la tubería para llamar a game_over(), no hacer que rebote en ella. Si usáramos StaticBody2D, el pájaro simplemente rebotatría en la tubería y el juego seguiría.

Selecciona el nodo → Inspector → Texture → arrastra art/sprites/pipe-green.png desde el FileSystem.

4.3
Añade un hijo CollisionShape2D.

Forma: RectangleShape2D, tamaño 48 × 320. Este rectángulo debe cubrir el área del sprite de la tubería.

05

Crea el Par de Tuberías (Pipe_game)

Dos tuberías + hueco de puntuación + movimiento + autodestrucción

5.1
Nueva escena — nodo raíz: Node2D.

Renómbralo Pipe_game.

5.2
Instancia pipe.tscn dos veces como hijos.

Clic derecho en Pipe_game → Instanciar escena hijo → selecciona pipe.tscn. Repite.

  • PipeDown (tubería superior): rotation = 180° (3.1416 rad), posición Y = -224
  • PipeTop (tubería inferior): posición Y = 224
¿Por qué giramos PipeDown 180° en lugar de tener otro sprite?

La tubería superior es exactamente la misma imagen que la inferior, pero boca abajo. En lugar de crear y mantener un sprite separado, simplemente rotamos la instancia 180°. Menos assets, menos trabajo. Cuando el par de tuberías se mueve, ambas se mueven juntas porque son hijas del mismo nodo padre Pipe_game.

¿Por qué Y=-224 y Y=224?

La pantalla tiene 512 píxeles de alto. El hueco entre tuberías mide 144 píxeles (definido por AreaAddPoint). Colocando cada tubería a 224 píxeles del centro en eje Y, dejamos 448 píxeles ocupados por tuberías y 64 libres como hueco por el que volar. La posición exacta en Y varía en cada instancia gracias a randi_range() en el script.

5.3
Añade un VisibleOnScreenNotifier2D en posición X = 120.
¿Para qué sirve VisibleOnScreenNotifier2D?

Si generamos tuberías constantemente sin eliminarlas, acumularíamos cientos de objetos en memoria aunque no se vean. VisibleOnScreenNotifier2D emite una señal (screen_exited) cuando el nodo sale de la pantalla. La conectamos para llamar a queue_free() y destruir la tubería automáticamente. Lo colocamos en X=120 (al borde derecho del par) para que la notificación se dispare justo cuando la última parte de la tubería sale de la vista.

5.4
Añade un Area2D llamado AreaAddPoint.

Dentro: CollisionShape2D con RectangleShape2D de tamaño 20 × 144 en posición X = 64. Este rectángulo vertical define el hueco por el que debe pasar el pájaro para puntuar.

¿Por qué un área invisible para los puntos y no comprobar la posición del pájaro?

Podríamos comparar la posición X del pájaro con la de cada tubería en cada frame, pero sería más complejo y menos preciso. El Area2D con un CollisionShape2D hace exactamente eso de forma automática y eficiente: cuando el pájaro físicamente cruza el rectángulo invisible, Godot dispara la señal body_entered. Cero matemáticas extra, detección perfecta.

5.5
Añade los AudioStreamPlayer2D:
  • AudioGameOver → hit.wav — con process_mode = Always para que suene aunque el juego esté pausado
  • AudioPoint → point.wav
¿Por qué process_mode = Always en AudioGameOver?

Cuando el pájaro choca, llamamos a Global.game_over() que pausa toda la escena. Si el audio del golpe no tiene process_mode = Always, también se pausaría en el mismo instante y no se escucharía nada. Al ponerlo en Always, este nodo específico sigue funcionando aunque el árbol esté pausado.

📦 Pipe_game [Node2D] ← pipe_game.gd ├── AudioGameOver [AudioStreamPlayer2D · Always] ├── AudioPoint [AudioStreamPlayer2D] ├── PipeDown [instancia pipe.tscn · rot 180°] ├── PipeTop [instancia pipe.tscn] ├── VisibleOnScreenNotifier2D [pos X=120] └── AreaAddPoint [Area2D] └── CollisionShape2D [20×144]
5.6
Crea el script pipe_game.gd y asígnalo. 
GDScript — pipe_game.gdextends Node2D

var velocity = 200  # píxeles por segundo hacia la izquierda

func _ready() -> void:
    position.x = 330                        # aparece fuera de pantalla por la derecha
    position.y = randi_range(133, 300)     # altura aleatoria en cada aparición

func _process(delta: float) -> void:
    position.x -= delta * velocity          # se mueve a la izquierda

func _on_visible_on_screen_exit() -> void:
    queue_free()                              # se destruye al salir de pantalla

func _on_pipe_bird(body: Node2D) -> void:
    if body is Bird:
        Global.game_over()
        $AudioGameOver.play()

func _on_area_add_point_body_entered(body: Node2D) -> void:
    if body is Bird:
        Global.increment_score()
        $AudioPoint.play()
¿Por qué el movimiento usa _process y no _physics_process?

Las tuberías no tienen físicas propias ni colisionan activamente — solo se desplazan horizontalmente y detectan entradas. Como no llamamos a move_and_slide() ni interaccionamos con el motor de físicas directamente, _process es suficiente y más eficiente. El costo de sincronización de físicas se ahorra para los nodos que realmente lo necesitan (el pájaro).

Conecta las señales desde la pestaña "Nodo":

  • VisibleOnScreenNotifier2D → señal screen_exited → _on_visible_on_screen_exit

06

Crea la Interfaz (GUI)

Puntuación, pantalla de inicio y Game Over — siempre visible por encima del juego

6.1
Nueva escena — nodo raíz: CanvasLayer.

Renómbralo GUI.

¿Por qué CanvasLayer para la interfaz?

Los nodos normales de Godot se renderizan en el "espacio del mundo": si hay una cámara que se mueve, los elementos se desplazan. CanvasLayer dibuja sus hijos en un espacio independiente, siempre pegado a la pantalla, sin importar lo que haga la cámara o cómo se mueva el escenario. Además, su propiedad layer (por defecto 1) garantiza que se dibuje por encima de todo el juego. Es el nodo estándar para HUDs e interfaces en Godot.

  • Sprite2D → renómbralo Message. Textura: message.png. Posición central (136, 280).
  • Sprite2D → renómbralo Gameover. Textura: gameover.png. Posición central (136, 216).
📦 GUI [CanvasLayer] ← gui.gd ├── LabelScore [Label · fuente 50px] ├── Message [Sprite2D ← message.png] └── Gameover [Sprite2D ← gameover.png]
6.3
Crea el script gui.gd y asígnalo. 
GDScript — gui.gdextends CanvasLayer

func _ready() -> void:
    # Nos suscribimos a las señales de Global
    Global.connect("on_increment_score", change_score)
    Global.connect("on_game_over", game_over)
    
    $Gameover.hide()     # oculto al inicio
    $Message.show()      # pantalla de inicio visible
    get_tree().paused = false  # despausa al recargar la escena

func _input(event: InputEvent) -> void:
    if Input.is_action_just_pressed("ui_accept"):
        if Global.is_start == false:
            Global.game_start()
            game_start()

func game_start():
    $Message.hide()

func game_over():
    $Gameover.show()
    await get_tree().create_timer(2).timeout
    get_tree().reload_current_scene()

func change_score():
    $LabelScore.text = str(Global.score)
¿Qué hace await exactamente?

await pausa la ejecución de esa función hasta que ocurra el evento indicado, pero sin bloquear el resto del juego. Es como decir "para aquí y espera, pero el resto del mundo sigue funcionando". En este caso, espera 2 segundos y luego recarga la escena. Sin await, tendríamos que usar señales del Timer o callbacks, lo cual es más verboso.

¿Por qué get_tree().paused = false en _ready?

Cuando el juego termina, llamamos a get_tree().paused = true. Luego recargamos la escena con reload_current_scene(). Pero el estado de pausa persiste entre recargas. Si no lo ponemos a false en _ready, el juego recargado arrancará pausado y el pájaro no se moverá. Este false "resetea" ese estado al inicio de cada partida.

07

Monta la Escena Principal (Level)

Fondo animado, suelo, pájaro, GUI, timer y zona de suelo

7.1
Nueva escena — nodo raíz: Node.

Renómbralo Level.

¿Por qué Node y no Node2D como raíz?

Node2D añade propiedades de posición, rotación y escala 2D, que el nodo raíz de una escena de juego no necesita (no lo vamos a mover). Usar Node básico es más limpio: indica que este nodo es un "gestor" o "contenedor lógico", no un objeto con presencia en el mundo 2D.

7.2
Añade el fondo animado: Parallax2D → ParallaxBackground.

En el Inspector: repeat_size = Vector2(288, 0) · autoscroll = Vector2(-30, 0)

Dentro añade un Sprite2D con la textura background-day.png en posición (144, 256).

¿Qué es Parallax2D y por qué lo usamos?

Parallax2D es un nodo diseñado para hacer scroll de fondos de forma automática y eficiente. Sin él, tendríamos que mover el sprite del fondo manualmente en el script, gestionar cuándo ha salido de pantalla y reposicionarlo — varias líneas de código propenso a errores.

Con las dos propiedades que configuramos: repeat_size le dice "cuando el fondo se desplace esta distancia, reptílate seamlessly" y autoscroll le dice "muévete automáticamente a esta velocidad en píxeles/segundo". El resultado: un fondo que hace scroll solo, sin una línea de código.

¿Por qué repeat_size = 288 y autoscroll.x = -30?

repeat_size = 288 coincide exactamente con el ancho de la ventana (y del sprite del fondo). Así el loop del fondo es perfectamente continuo, sin costuras visibles. autoscroll.x = -30 (negativo = hacia la izquierda) crea la ilusión de que el pájaro avanza hacia la derecha. El valor 30 es más lento que las tuberías (200) para dar sensación de profundidad: lo lejano se mueve más despacio.

Instancia gui.tscn como hijo de ParallaxBackground.
7.4
Añade el suelo: otro Parallax2D llamado ParallaxFloor.

Hijo directo de Level (no de ParallaxBackground). repeat_size = Vector2(336, 0) · autoscroll = Vector2(-60, 0)

Dentro: Sprite2D con base.png en posición (288, 464), escala X = 1.714.

¿Por qué el suelo va al doble de velocidad que el fondo?

El fondo va a -30 píxeles/segundo y el suelo a -60. Esta diferencia de velocidad crea el efecto de parallax: los elementos más cercanos parecen moverse más rápido que los lejanos, igual que ocurre en la vida real cuando miras por la ventana de un coche. El fondo (nubes, ciudad lejana) se mueve despacio; el suelo (lo más cercano) se mueve rápido. Esto da una sensación de profundidad y movimiento mucho más convincente.

7.5
Instancia el pájaro.

Clic derecho en Level → Instanciar escena hijo → bird.tscn. Posición: (120, 112). z_index = 1 para que se dibuje por encima del fondo.

¿Para qué sirve z_index?

En Godot 2D, los nodos se dibujan en el orden en que aparecen en el árbol (los de abajo encima de los de arriba). z_index permite saltarse ese orden: un nodo con z_index=1 siempre se dibuja por encima de nodos con z_index=0. Esto garantiza que el pájaro se vea por encima del fondo y el suelo independientemente de su posición en el árbol.

7.6
Añade el Timer para generar tuberías.

Nodo Timer hijo de Level, nombre: TimerPipe. wait_time = 1.5 segundos.

¿Por qué un Timer y no generar tuberías en _process?

Podríamos acumular tiempo en una variable en _process y generar una tubería cada vez que supere 1.5 segundos. Pero el nodo Timer ya hace eso de forma optimizada, con señales limpias, pausable y sin que tengamos que gestionar la lógica manualmente. Usar nodos especializados es siempre preferible a reinventar la rueda en el script.

7.7
Añade el área de detección del suelo: Area2D → AreaFloor.

Dentro: CollisionShape2D con RectangleShape2D de tamaño 572 × 64 en posición (290, 440). Justo sobre el suelo visible.

¿Por qué no usamos el suelo (Parallax2D) directamente para detectar la colisión?

El Parallax2D con su Sprite2D no tiene colisión física — es solo visual. Podríamos añadir un StaticBody2D para que el pájaro rebote en el suelo, pero en Flappy Bird queremos que tocar el suelo signifique perder directamente, no rebotar. El Area2D (zona de detección) es exactamente lo que necesitamos: detecta el toque y llama a game_over().

GDScript — level.gdextends Node

# @export hace que esta variable aparezca en el Inspector del editor
@export var pipe_game_scene: PackedScene

func _ready() -> void:
    Global.connect("on_game_start", game_start)

func game_start():
    $TimerPipe.start()   # arranca el generador de tuberías

func create_pipe():
    var pipe = pipe_game_scene.instantiate()
    add_child(pipe)

func _on_timer_pipe_timeout() -> void:
    create_pipe()

func _on_area_floor_body_entered(body: Node2D) -> void:
    if body is Bird:
        Global.game_over()
        $TimerPipe.stop()    # evita generar más tuberías al perder
        $AudioGameOver.play()
¿Qué es PackedScene e instantiate()?

Una PackedScene es un recurso que contiene una escena completa "empaquetada" lista para ser clonada. instantiate() crea una copia nueva en memoria de esa escena. Es el equivalente a tener una plantilla de Word y crear un documento nuevo a partir de ella cada vez que quieres uno.

Cada vez que el Timer dispara, creamos una copia nueva de pipe_game.tscn con su propia posición Y aleatoria, su propia velocidad, y la añadimos a la escena. Cuando sale de pantalla, se destruye sola. No acumulamos objetos en memoria.

¿Por qué usamos @export para asignar la escena?

Podríamos cargar la escena directamente en el código: preload("res://scenes/pipe_game.tscn"). Pero si algún día movemos el archivo a otra carpeta, el código se rompe. Con @export, la asignación se hace desde el Inspector arrastrando el archivo. Godot gestiona la referencia internamente y si el archivo se mueve dentro del proyecto, la actualiza automáticamente.

⚠ Problema: el pájaro cae antes de pulsar Espacio

Revisa en bird.gd que la gravedad (velocity += get_gravity() * delta) esté dentro del bloque if Global.is_start:. Si está fuera, la gravedad actúa siempre, incluso en la pantalla de inicio.

⚠ Problema: las tuberías no aparecen

Comprueba que en el Inspector del nodo Level la variable Pipe Game Scene tiene asignada pipe_game.tscn. Si está vacía, el instantiate() fallará silenciosamente. También verifica que la señal timeout del Timer está conectada.

⚠ Problema: el juego arranca pausado después del primer reinicio

Asegúrate de que en gui.gd el _ready() incluye get_tree().paused = false. Sin esta línea, el estado de pausa del Game Over persiste al recargar la escena.
